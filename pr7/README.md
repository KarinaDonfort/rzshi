# ПР7. Мультимодальний аналіз і структуроване вилучення даних

Матеріали до сьомої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР7.pdf`, виданому до заняття.

## Задача коротко

Постачальники надсилають магазину «Сузірʼя» рахунки на оплату — сканами, фото з телефона, знімками екрана. Бухгалтерія переписує з них реквізити й суми в реєстр платежів. Ви будуєте застосунок, у якому це робить **мультимодальна модель**: читає зображення рахунку й повертає заданий набір полів у структурованому вигляді. А далі — те, що робить його придатним для грошей: **код** перевіряє вилучене за схемою і програмними правилами (контрольні суми IBAN і ЄДРПОУ, арифметика рядків і ПДВ, дати, покупець, довідник постачальників) і вирішує, чи можна документ пропустити без людини.

Наприкінці — прогін якісних і навмисно погіршених зразків і відповідь на питання, скільки помилок моделі ловлять ваші правила, а скільки проходять тихо.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Каркас застосунку |
| `samples/` | 9 рахунків гарної якості, 18 погіршених варіантів, правильні значення в `expected.json`; опис — у `samples/README.md` |
| `reference/` | Реквізити своєї компанії й довідник постачальників — для правил |
| `degrade.py` | Погіршити зображення самостійно: розмиття, масштаб, контраст, поворот, обрізання, шум, JPEG |
| `requirements.txt` | Залежності роботи |
| `.env.example` | Зразок налаштувань: доступ до моделі, обмеження на зображення |
| `check_env.py` | Перевірка середовища: Python, пакети, `.env`, зразки, пробний запит до моделі із зображенням |
| `eval/` | Перевірка на зразках: якісні проти погіршених |

```
app/
├─ main.py                веб-рівень: сторінка, /api/samples, /api/extract, зразки як статичні файли
├─ images.py              перевірка й підготовка зображення
├─ llm.py                 multimodal-запит, структурована відповідь і обробка збоїв
├─ schema.py              контракт відповіді моделі та перевірка JSON Schema
├─ rules.py               програмні перевірки й читання довідників
├─ extraction.py          конвеєр і рішення auto / review / reject
└─ templates/index.html   сторінка: зображення, рішення, проблеми, поля, позиції
```

Сторінка показує зразок або завантажений файл, надсилає його на розбір і показує рішення з причинами, проблеми, вилучені поля (ті, на які вказує проблема, підсвічено), позиції та метрики запиту. Відповідь моделі перевіряється схемою до бізнес-правил.

## Початок роботи

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
python check_env.py
```

Для macOS і Linux активація середовища — `source .venv/bin/activate`, копіювання — `cp .env.example .env`.

Ключ доступу перенесіть у `.env` з папки попередньої роботи.

**Запустіть `check_env.py` заздалегідь.** Він надсилає моделі невелике зображення з числом — покаже, чи приймає обрана модель зображення, скільки триває відповідь і скільки токенів коштує навіть крихітна картинка.

Запуск застосунку з папки `pr7`:

```bash
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000.

## Що очікує сторінка

Розбір — `POST /api/extract` з файлом у полі форми `image`. JSON-відповідь містить рішення, причини, документ після перевірки схемою, проблеми, інформацію про зображення, модель, час, токени, сиру JSON-відповідь і `finish_reason`. Збій провайдера повертається як HTTP 502, а не як рішення про відхилення документа.

## Що реалізувати

| Де | Що зробити |
|---|---|
| `app/images.py` → `prepare` | Перевірити, що файл — придатне зображення; врахувати орієнтацію; зменшити й перекодувати для моделі; позначити можливе обрізання вмісту на краю |
| `app/schema.py` → `output_schema`, `validate` | Контракт відповіді: заданий набір полів, типи, відсутні значення |
| `app/llm.py` → `get_client`, `build_messages`, `extract` | Інструкція для вилучення, запит із зображенням, виклик, перевірка, збої |
| `app/rules.py` → `check` | Програмні правила: IBAN, коди, арифметика, дати, покупець, довідник, обовʼязкові поля |
| `app/extraction.py` → `decide`, `process` | Конвеєр і рішення `auto` / `review` / `reject` з причинами |
| `app/main.py` → `api_extract` | Обробити збої: порожній чи завеликий файл, не зображення, збої моделі, невалідна відповідь |
| `eval/` | Прогін зразків, власні зразки, порівняння з `expected.json`, одна зміна, висновки |

Рішення, які стоять за кожним пунктом, перелічені в розділі 2 практичної роботи — продумайте їх до того, як писати код.

## Чекліст самоперевірки

- [ ] Застосунок приймає зображення рахунку й повертає заданий набір полів; відповідь моделі перевіряється за схемою.
- [ ] Значення, якого в документі немає або якого не видно, повертається як відсутнє, а не вигадується.
- [ ] Правила перевіряють IBAN, коди, арифметику, дати, покупця й довідник постачальників; кожна проблема вказує на поле.
- [ ] Рішення `auto` / `review` / `reject` ухвалює код за результатами перевірок, а не модель; причини показано.
- [ ] Текст у документі, адресований «системі обробки», не впливає на рішення.
- [ ] Сторінка показує рішення, проблеми, поля, позиції, розміри зображення до й після підготовки, час, токени.
- [ ] Застосунок не падає: порожній, завеликий файл і не зображення, збій моделі, невалідна відповідь дають зрозумілу помилку.
- [ ] Модуль зображень не знає про модель, модель — про правила, веб-рівень — ні про що з цього.
- [ ] Ключ не потрапив ані в код, ані в репозиторій.
- [ ] Прогнано всі зразки й щонайменше два власні; порівняно з правильними значеннями по варіантах; пораховано тихі помилки; одну зміну перевірено окремо; висновки записано.
- [ ] Ви можете пояснити кожне ухвалене рішення.
